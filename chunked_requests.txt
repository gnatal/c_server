Chunked Transfer-Encoding — manual test commands
=================================================

Start the server first (from the project root):
  make && PORT=8099 ./build/bin/cexpress

curl only sends a real "Transfer-Encoding: chunked" body when you force the
header yourself with -H — otherwise it computes a Content-Length and sends
that instead. Add -v to any of these to see the actual chunk framing
("Wiki\r\n" etc.) go out on the wire.

1. Basic chunked POST — GET /echo just echoes the (decoded) body back
------------------------------------------------------------------
curl -v -X POST -H "Transfer-Encoding: chunked" \
  --data-binary "Hello chunked world" \
  http://localhost:8080/echo

Expect: 200 OK, body "Hello chunked world", Content-Length: 20 on the
response (computed from the decoded body, not the chunked wire size).

2. Chunked JSON body against an authenticated route (POST /echo/json)
-----------------------------------------------------------------
curl -v -X POST -H "Transfer-Encoding: chunked" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer my-secret-api-key" \
  --data-binary '{"hello":"world"}' \
  http://localhost:8080/echo/json

Expect: 200 OK, JSON echoed back. Drop the Authorization header to see the
401 this route enforces regardless of chunked vs. Content-Length framing.

3. Chunked application/x-www-form-urlencoded body (POST /form)
------------------------------------------------------------
curl -v -X POST -H "Transfer-Encoding: chunked" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-binary "name=natal&age=32" \
  http://localhost:8080/form

Expect: 200 OK, {"name":"natal","age":"32"} — same parsing as a
Content-Length-framed form body, just decoded from chunks first.

4. Large chunked body — exercises conn->in_buf growth (see lib/CLAUDE.md,
   "Chunked Transfer-Encoding")
-------------------------------------------------------------------------
head -c 50000 /dev/urandom | base64 > /tmp/chunked_big.txt
curl -sD - -X POST -H "Transfer-Encoding: chunked" \
  --data-binary @/tmp/chunked_big.txt \
  http://localhost:8080/echo -o /tmp/chunked_big_echo.txt
diff /tmp/chunked_big.txt /tmp/chunked_big_echo.txt && echo "round-trip OK"

Expect: no diff output, "round-trip OK" — the ~67KB body (base64-inflated)
is well beyond BUF_SIZE (8192), forcing the server to grow its buffer
mid-request.

5. Chunked upload throttled to force multiple small TCP reads
-------------------------------------------------------------
curl -v -X POST -H "Transfer-Encoding: chunked" \
  --limit-rate 1K \
  --data-binary @/tmp/chunked_big.txt \
  http://localhost:8099/echo -o /dev/null

Expect: 200 OK (slower - --limit-rate spreads the body across many recv()
calls, exercising the same code path as #4 without needing as much data).


Bonus: edge/error cases curl can't produce on its own
======================================================
curl always sends well-formed chunk framing and won't let you send both a
real chunked body and a Content-Length header at once - these three cases
(the security/robustness paths this feature added) need raw control over
the bytes on the wire, via a plain TCP client instead:

6. Transfer-Encoding + Content-Length together -> 400 Bad Request
   (RFC 7230 3.3.3 - rejected as an ambiguous/smuggling-shaped message)
-------------------------------------------------------------------------
printf 'POST /echo HTTP/1.1\r\nHost: localhost\r\nTransfer-Encoding: chunked\r\nContent-Length: 4\r\n\r\n4\r\ntest\r\n0\r\n\r\n' \
  | nc -w1 localhost 8099

Expect: HTTP/1.1 400 Bad Request

7. Malformed chunk size (non-hex) -> 400 Bad Request
-----------------------------------------------------
printf 'POST /echo HTTP/1.1\r\nHost: localhost\r\nTransfer-Encoding: chunked\r\n\r\nZZ\r\ntest\r\n0\r\n\r\n' \
  | nc -w1 localhost 8099

Expect: HTTP/1.1 400 Bad Request

8. Declared chunk size beyond MAX_BODY_SIZE (10 MiB) -> 413 Payload Too Large
   (rejected as soon as the chunk-size line is parsed, no need to actually
   send that much data)
-------------------------------------------------------------------------
printf 'POST /echo HTTP/1.1\r\nHost: localhost\r\nTransfer-Encoding: chunked\r\n\r\nB00000\r\n' \
  | nc -w1 localhost 8099

Expect: HTTP/1.1 413 Payload Too Large
