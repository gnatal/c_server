# tests/ — test harness & verification

## Architecture
Standalone unit and integration test suites compiled independently into `build/bin/test_*`. Tests run without third-party test frameworks using standard C `<assert.h>` assertions and return exit code 0 on complete pass. `make test` runs 18 suites (all pass on macOS with gcc-16, plain and under ASan + UBSan, as of 2026-09-23; not run on Linux for this update; `test_connection`, `test_pipelining`, `test_stream` and `test_answered` also run against the epoll backend through epoll-shim with `make test_epoll`):
- `test_middleware.c`: Middleware chain dispatching, synchronous execution ordering, termination by early response, 404/405 fallthrough (unmatched path vs. path matched under a different method), and error propagation via `chain_error`.
- `test_router.c`: Route registration (no per-App cap since the Patricia tree; `MAX_ROUTER_ROUTES` per Router, and `app_mount` under that cap), literal pattern matching, parameter tokenization (`:id`), `*` wildcard matching (mid-pattern and trailing), route param lookup (`req_get_param`), `match_route` (HEAD→GET fallback, explicit HEAD wins) and `match_route_allowed_methods` (the method list behind a 405 response). The standalone `match_path` matcher is tested separately from the tree. Covers two routes naming the same parameter position differently, a `:param` registered after a mid-pattern `*` at the same position, a literal beating a `:param`, and a backtrack from a dead-end literal branch into a param route (only that route's own captures survive). Its `cleanup_app` frees only `app->connections`, so route trees leak at exit; harmless on macOS, but a Linux LeakSanitizer run would report them. Also covers `app_use_body_limit`/`app_body_limit_for_path`: the global `MAX_BODY_SIZE` default with no registrations, prefix scoping at a segment boundary, the longest matching prefix winning regardless of registration order, an unscoped `""`/`NULL` prefix applying everywhere, a `max_bytes` above `MAX_BODY_SIZE` getting clamped down (never loosened), and the `MAX_BODY_LIMITS` registration cap being enforced rather than overflowed.
- `test_http_parser.c`: Pure buffer parsing of HTTP/1.1 request lines, query-string splitting (`parse_query_string`) and lookup (`req_get_query`), header parsing (`parse_headers`) and lookup (`req_get_header`), URL-decoding (`url_decode`), Content-Length bounds enforcement (including the 413-vs-400 sentinel split), a body beyond the old `BUF_SIZE`, keep-alive header determination, and chunked framing: `chunked_body_scan`/`chunked_body_decode`, plus `test_chunked_body_scan_resume` (resumed scans fed one byte at a time give the same verdict and decoded length as a from-scratch scan of every prefix; bytes before `state.pos` are never re-read; the trailer search resumes via `trailer_from`) and `test_request_wire_len` (headers only, `Content-Length`, and chunked-with-trailer requests each end exactly where a following request starts). `test_parse_http_request_in_place`: for a `Content-Length` body followed by a pipelined request, a body ending the buffer, no body, and a chunked body with an extension, a trailer and a request behind it, the in-place parse matches `parse_http_request` (same fields, same body bytes), `req->body` is `raw + header_len`, the returned byte restores everything after the request (and for `Content-Length` the whole buffer is unchanged); binary chunk data with embedded NULs whose in-place move overlaps; a malformed chunk returns `-1` and leaves the buffer byte-for-byte unchanged. `format_http_date` against reference IMF-fixdates (epoch, RFC 9110 example, leap days, 2100, year 9999, pre-epoch clamp) and `http_date_for` reusing one buffer and reformatting only on a new second.
- `test_http_hardening.c` (split from `test_http_parser.c` to stay far below the 1,000-line cap): regressions for header names matched by substring (`X-Content-Length`, text in the request target or in a body), overlong method token, `Connection:close` without a space, strict / duplicate / conflicting `Content-Length`, `Content-Length` with chunked, parsing into a garbage-filled `Request`, header-value whitespace and limits, percent escapes at buffer boundaries. Also covers `request_framing`'s optional `path_out`/`path_len_out` params (added so `connection.c` can look up a body limit by path before a `Request` exists) returning a pointer into the caller's own buffer, not a copy. Also covers `parse_http_request`'s `-3` return: a header value or name that would not fit `MAX_HEADER_VALUE_LEN`/64 is rejected rather than truncated, a value comfortably within the raised cap (a realistic ~600-char JWT-shaped `Authorization: Bearer` token) round-trips exactly through `req_get_header` uncut, and `parse_headers` (the separate `void` component parser this suite also exercises directly, not on the live request path) is left deliberately still-truncating since it has no return value to signal a rejection through. Also covers `parse_http_request`'s `-4` return and `url_decode`/`parse_query_string`'s `-1` return: `%00` decoding into a real NUL in the path or a query name/value is rejected rather than silently truncating everything downstream that reads it as a C string (the exact `GET /static/style.css%00.png` shape `improvements.md` measured being routed as `/static/style.css`), while an ordinary percent-encoded path/query with no embedded NUL is unaffected. Also covers malformed request lines (`test_malformed_request_line_rejected`): a request line picohttpparser rejects outright (no HTTP version, `HTTP/2.0`, plain garbage) now makes `request_is_complete` return `1` instead of `0` (the actual bug - it used to say "need more bytes" forever), while `parse_http_request`/`request_framing` still report it as malformed (`-1`); a genuinely incomplete request line is confirmed to still report `0`/incomplete, unaffected by the fix. Also covers `test_short_version_token_rejected` (a version token under 9 bytes after a finished head is malformed, not "incomplete" forever; prefixes with no blank line yet still wait; a leading CRLF still parses) and `test_every_prefix_is_answered_or_waits_for_bytes` (the fuzzer's answered-or-closed oracle, deterministically, over every prefix of 15 inputs in exact-size buffers). Also covers bare-LF rejection: `test_bare_lf_rejected` - a bare `\n` terminating the request line, a header line, or the final blank line is now malformed (`-1`, `request_is_complete` reports `1`/immediate rejection), while a fully CRLF-terminated request is unaffected; `test_transfer_encoding_token_matching` - a `Transfer-Encoding` value is chunked framing only when it is exactly the single token `chunked` (OWS/case tolerant), with a table covering a substring lookalike (`xchunked`/`chunkedx`), an unsupported coding alone (`gzip`), `chunked` alongside another coding in either order, a duplicate `chunked, chunked`, and the same coding split across two separate `Transfer-Encoding` header instances - all rejected (`-3`, distinct from `parse_http_request`'s own already-retired top-level `-3`) rather than the old substring search's false-positive on any of these.
- `test_connection.c`: Non-blocking socket I/O, `handle_readable` buffer progression, keep-alive connection reuse (sequential requests; pipelining has its own suite, `test_pipelining.c`), partial buffer reads, header buffer overflow cutoff (431 Request Header Fields Too Large), 400 for a bad `Content-Length`, 400 for a malformed request line (`test_handle_readable_malformed_request_line_400`; previously untested and, before the fix, never actually answered), 400 for a bare-`\n`-terminated request line and 501 for an unsupported/ambiguous `Transfer-Encoding` (`test_handle_readable_bare_lf_400`, `test_handle_readable_unsupported_transfer_encoding_501`), a body beyond `BUF_SIZE` growing `conn->in_buf` (and freeing it once idle - `in_buf == NULL`, `in_cap == 0`), a `Content-Length` beyond `MAX_BODY_SIZE` (413), chunked bodies (including `test_handle_readable_chunked_scan_resumes_and_resets`: `conn->chunk_scan` advances only at completed chunk boundaries across split reads, and is zeroed by the keep-alive reset so a second chunked request on the same connection frames correctly), 414, idle-timeout sweeps, graceful stop, and file streaming, via POSIX `socketpair(2)` connected to an isolated event-loop instance without binding to physical network ports. Also covers the `request_started` deadline: a "slow-drip" partial request that keeps `last_activity` fresh but exceeds `REQUEST_HEADER_TIMEOUT_SECONDS` still gets an explicit 408 and is closed; a fresh partial request within that deadline is left alone; a pending body past the header deadline but within the longer `REQUEST_BODY_TIMEOUT_SECONDS` survives, and past the body deadline gets 408'd too. Also covers the `last_write_progress` deadline: a pending response manually backdated past `WRITE_TIMEOUT_SECONDS` is reclaimed with no response sent, one still making recent progress is left alone, and — end to end through the real `flush_connection` path rather than a poked field — an 8 MiB response over a `socketpair(2)` with nobody ever reading the peer end genuinely hits `EAGAIN` partway through (asserted via `out_sent < out_len`), proving `flush_connection` itself arms the clock before the sweep reclaims the stalled connection. Also covers `accept_client` (`test_accept_client_socket_options`, on a real loopback listener): the listener has `TCP_NODELAY`, and a socket from `accept_client` - and one admitted through `accept_connections` - is non-blocking with `TCP_NODELAY` without any per-connection `fcntl`/`setsockopt` (and `FD_CLOEXEC` on Linux), and `accept_client` on a drained listener returns `EAGAIN` instead of blocking; this is the per-platform check of the listener inheritance the accept path relies on. On Linux (Docker, 2026-09-23) this suite stops earlier, at `test_accept_connections_emfile_frees_a_slot_and_recovers` (`app_count_connections == 0` fails - pre-existing, same on `HEAD` before that test encodes macOS's behavior of destroying the connection that hit `EMFILE`, and Linux evidently keeps it queued so the retry accepts it). Also covers `accept_connections`' overload shedding, which needs a real loopback TCP listener rather than `socketpair(2)` (`setup_test_server`/`connect_loopback_client`/`drain_accept_connections`, the last a short retry loop absorbing a rare connect()-returned-before-visible-to-accept() race seen occasionally under ASan): `max_connections` accepts up to the cap and sends an explicit 503 + `Connection: close` beyond it (and `0` means uncapped); and, simulating real fd exhaustion via `setrlimit(RLIMIT_NOFILE, ...)` pinned to the descriptors already in use, forcing a genuine `EMFILE` from `accept()` — MEASURED that the triggering connection is unrecoverable (the kernel discards it before the error is even visible), so the test asserts what the fix actually delivers: the spare fd frees a slot so the *next* connection is accepted normally, and `connection_close` re-arms the spare fd the moment anything closes. Also
  covers body-buffer growth: `conn->in_cap` grows by doubling rather than jumping straight to the declared `Content-Length` in one
  step (checked once, right after the first growth past `BUF_SIZE`, while only a few KB of a 5 MiB declared body have
  actually arrived - regression for the MEASURED "+3,000 MB virtual for 300 connections" problem in `improvements.md`);
  and `app_use_body_limit`: a declared `Content-Length` over a route's configured limit gets 413 immediately (connection
  closed, nothing buffered), while one within the limit is unaffected. Also covers the header-limit fix end to end (distinct from the
  whole-header-block-over-`BUF_SIZE` 431 above: a request that fits comfortably under `BUF_SIZE` but carries one header
  value past `MAX_HEADER_VALUE_LEN`, exercising `parse_http_request`'s `-3` → `connection.c`'s 431 mapping specifically).
  Also covers embedded-NUL rejection end to end: `GET /static/style.css%00.png` (the exact shape `improvements.md` measured being
  routed and served as `/static/style.css`) now gets an explicit 400 and the connection is closed, exercising
  `parse_http_request`'s `-4` → `connection.c`'s 400 mapping.
- `test_pipelining.c` (split from `test_connection.c`, which is past the 1,000-line cap, same `socketpair(2)` harness): two GETs in one write answered in order; a `Content-Length` body and a chunked body with a trailer each followed by a GET (the next request starts at `request_wire_len`, not at `in_len`); one request plus half of the next (the half is compacted to `in_buf[0]` with its request clock running, then completed by the next read); `MAX_PIPELINED_PER_EVENT + 4` requests (16 served, the last 4 copied off `App.read_buf` into an owned buffer at offset 0, write interest armed, `handle_writable` serves them with no new input and the owned buffer is freed); `Connection: close` on the first request drops the second; a malformed second request gets 400 after the first's 200; and a 1 MiB response that hits `EAGAIN` with requests pipelined behind it (read interest dropped, later input not consumed while pending, the follow-up answers arrive after the big body, in order, once it drains).
- `test_read_buf.c` (separate suite, `test_connection.c` is past the 1,000-line cap; same `socketpair(2)` harness, with the client-to-server `SO_SNDBUF` raised so one write can exceed `BUF_SIZE`): a fresh connection and one between keep-alive requests have `in_buf == NULL`; connection A's partial request (header view and body bytes) survives connection B being served out of the same `App.read_buf` in between; a body past `BUF_SIZE` read into `App.read_buf` moves to an owned grown buffer with every byte carried over (never a realloc of the shared one); a request pipelined behind a response that hits `EAGAIN` is copied off `App.read_buf` (compacted, `in_len == request_len + follow-up`) and still answered after another connection used the shared buffer; 400 and 431 rejections straight from the borrowed buffer leave it usable by the next connection (ASan catches a wrong `free`); `close_idle_connections`' 408 on an owned partial buffer. `test_body_is_a_view_into_the_input_buffer`: through a real connection, the handler's `req->body` lies inside `res->conn->in_buf` (the borrowed buffer for a small body, decoded in place for chunked, the grown owned buffer for 20,000 bytes) and is NUL-terminated, and a GET pipelined right behind a `Content-Length` body (its first byte held the NUL) is still answered. Verified to fail when `stop_borrowing_read_buf` is disabled.
- `test_stream.c` (producer streaming; own suite, `test_connection.c` is past the 1,000-line cap; same `socketpair(2)` harness, driving `handle_readable` / `handle_writable` / `close_idle_connections` / `app_wake_streams` by hand the way the event loop would): `stream_write` framing, exact-fit and refuse-whole-write bounds, `STREAM_WRITE_MAX` fitting an empty engine turn; `res_stream` commits a chunked head without calling the producer, drops trailers, turns later `res_write`/`res_end` into no-ops, and a later `res_send` replaces it and frees the ctx once; HEAD frees the ctx at once. Through the engine: a 12 MiB body (past `MAX_BODY_SIZE`) streamed with output never above one `STREAM_CHUNK_SIZE` turn, decoded byte-exact, the ctx freed exactly once, `stream_buf` released, and a `/ping` pipelined behind it answered afterwards on the same connection; an SSE producer parks (write interest dropped, read kept, not called again by a stray writable event), `app_wake_streams` only arms write interest, the next writable turn delivers the published events, and `STREAM_END` keeps the connection alive; the idle sweep resumes a parked stream instead of applying the write-stall deadline (stall clock restarted); a peer hang-up while parked closes and frees the ctx at once; a pipelined request while parked is left unread with read interest dropped, then served after the stream ends; `STREAM_ABORT` closes with no last chunk; `app_stop` lets a parked stream finish and then closes; HEAD through the engine sends headers only. `res_stream` on a 204 frees the ctx at once and writes the head only.
- `test_response.c`: `res_set_header` behavior - custom headers appear in the built response, same-name overwrite (case-insensitive), `Content-Length`/`Connection` rejected as reserved, a custom `Content-Type` overriding the default, and the `MAX_RESPONSE_HEADERS` cap being enforced rather than overflowed; cookies, redirects, chunked streaming, trailers, HEAD; header / cookie / trailer / redirect injection (CR LF), zero-valued `CookieOptions`, exact head bytes, `res_init` on a garbage-filled struct, a second send replacing the first. exact-byte checks go through `without_date`, which asserts the `Date:` line right after the status line and removes it; `Date` is rejected as reserved; a 204 / 304 / 103 is head-only on `res_send`, `res_write`+`res_end` (no chunks, no Trailer) and `res_send_file` (no fd kept), with an explicit `Content-Type` kept on a 304.
- `test_multipart.c`: `multipart/form-data` boundary extraction (quoted/unquoted, trailing parameters, non-multipart rejection), part splitting (fields, file parts, a binary payload with an embedded NUL byte), malformed/nameless parts being skipped, and the `MAX_MULTIPART_PARTS` truncation cap.
- `test_urlencoded.c`: `application/x-www-form-urlencoded` body splitting on `&`/`=`, `%XX`/`+` decoding, bare-key-gets-empty-value and skipped-empty-pair edge cases, `NULL`/empty bodies, and the `MAX_FORM_FIELDS` truncation cap.
- `test_static.c`: Traversal prevention (`..` rejection, symlink escape checks), custom MIME types, prefix stripping, and directory index fallback against a temporary filesystem sandbox. Also covers the in-memory file cache: a request within `STATIC_CACHE_REVALIDATE_SECONDS` of the same file's last check is served from the cache even after the file is deleted from disk (proves no filesystem call happened); past that window, an unchanged file is still served correctly (the mtime/size revalidation path, not the fast one), and a changed file's new content is picked up. Uses a real `sleep(2)` to clear the 1 s revalidation window (short enough not to matter for `make test`'s total runtime) and calls `static_cache_clear` afterward so the cache doesn't leak into the ASan build's process-exit state. `test_large_file_is_streamed_not_buffered`: a file one byte past `STATIC_CACHE_MAX_ENTRY_BYTES` leaves only the head in `out_buf` (with the full `Content-Length`) and an open `file_fd` with `file_remaining` equal to the file size, positioned at the file's first byte; a file of exactly the cap is still buffered whole with no fd; HEAD on the large file keeps no fd.
- `test_event_loop.c`: Cross-platform event-loop lifecycle (`event_loop_init`, `event_loop_close`, `event_loop_is_open`, `event_loop_backend_name`; asserts the union member that matches the reported backend: `app.ring` for io_uring, `app.epoll_fd` for epoll, `app.loop_fd` for kqueue; "none" before init and after close), read/write readiness polling via `socketpair(2)`, and idle/shutdown timer expiration verification. Also the backend contract `connection.c` relies on, run on every backend (kqueue here, epoll via `make test_epoll`, io_uring on Linux): 50 rounds of the keep-alive interest cycle (watch write, unwatch read, unwatch write, watch read, the redundant unwatch write) never produce `LOOP_EVENT_ERROR` and read readiness is still delivered (verified to fail on the old io_uring backend with exactly that error); readiness left in place (unread bytes, a writable socket) is reported on every poll - level-triggered - and a dropped interest is not; a closed fd with readiness pending leaks nothing to the next connection that reuses its number. `main` prints the backend each pass runs on; the first pass uses whatever `CEXPRESS_EVENT_LOOP` / automatic selection picks, and on a Linux build with io_uring, when that was not epoll, the whole contract runs again on forced epoll in a forked child (a process that has torn down an io_uring ring can see a spurious `EINTR` from its next `epoll_wait`; a fresh process is what a real epoll worker is). `test_backend_selection_env` (Linux and epoll-shim builds): an unknown `CEXPRESS_EVENT_LOOP` fails and leaves the loop closed, `epoll` gives epoll, `io_uring` gives io_uring or fails - never silently another backend - and an empty value means automatic. Linux results are from Docker, not CI: with the default seccomp profile (io_uring refused with `EPERM`, so the fallback path) and with `--security-opt seccomp=unconfined` (io_uring, then epoll).
- `test_cluster.c`: Worker count resolution, `SO_REUSEPORT` multi-bind, master supervisor process lifecycle, concurrent HTTP serving across workers, and synchronized graceful shutdown. Also covers the port preflight and restart budget, both by forking a real master process and blocking on its exit status rather than poking internal state (the relevant fields are `cluster.c`-local, not exposed): `test_cluster_master_exits_fast_when_port_is_taken` occupies the port on `INADDR_ANY` (matching `create_server_socket`'s own bind address exactly, so a mismatched-address false negative can't defeat the test) without `SO_REUSEPORT` and asserts the master exits non-zero in under 2 seconds - the preflight bind check catching the fatal-misconfiguration case before forking anyone, instead of the pre-fix respawn storm (10,594 respawns in ~4s, `improvements.md`). `test_cluster_master_exits_after_restart_budget_exceeded` registers a worker-init hook that `exit(7)`s immediately (a worker that can never come up) and asserts the master eventually exits with status 1 once the restart budget is exhausted, exercising the exponential-backoff-then-give-up path end to end (takes a few real seconds: the backoff schedule itself, 100/200/400/800/1600 ms, is what's being verified, not mocked out). `test_cluster_master_does_not_leak_client_fds` runs the master under `RLIMIT_NOFILE` 64 and sends 150 sequential `Connection: close` requests, each of which must end in EOF within 2 s: on the single acceptor a master that keeps its copy of a passed fd both suppresses the worker's FIN and runs out of fds (fails at request 0 on the unfixed code). On failure it drains the cluster before asserting so no orphaned workers keep the port open.
- `test_cookbook.c`: drives every recipe in `lib/examples/cookbook.c` through the real path (`parse_http_request` → `match_route` → `dispatch`) with a fake `Connection` and asserts exact status lines and bodies (JSON in/out through yyjson, middleware kinds, sub-router, cookies, forms, multipart with an embedded NUL, redirect safety, chunked streaming, HEAD, worker hook registration, and recipe 14's `res_stream` producers: `fetch` calls a recorded producer turn by turn as `flush_connection` would, checking the CSV export's exact chunk bytes, its 400 on a bad `rows`, and an SSE publish/replay including refusal of a message that would forge a second event). Links the static library.
- `test_ping.c`: a minimal `/ping` route (its own `handler_ping`, the same shape as the demo's inline one) through parse → route → dispatch: exact response bytes (with a fixed-width `Date` line), `Connection: close` detection, HEAD, 405 + `Allow`, 404. Links only the library (no SQLite).
- `bench_hotpath.c` (`make bench`): not a test. Prints ns/request for the pure request path and yyjson emitting a 20-row list. Also prints `sizeof(Request/Response/Connection)`.
- `test_body_limit.c` (own suite; same `socketpair(2)` harness as `test_pipelining.c`, with a `pump` helper that writes as fast as the socket takes it and runs `handle_readable` after each write): `request_target_path` (query dropped, `//` collapsed, `%75` decoded, the length bounds the target, `%2F`/`..`/`%00`/no leading `/` → -4, an over-long path part → -2 while a long query is fine) and `app_body_limit_for_target` (every bypass shape maps to the `/upload` limit; `/uploads`, a `/upload` inside the query, and a refused target get `MAX_BODY_SIZE`). Through the engine with a 16-byte limit: `Content-Length` on `/upload`, `/upload?x=1`, `//upload`, `/%75pload` and a chunked body on `/upload` and `//upload?x=1` all get 413; the same shapes within the limit (including 16 bytes framed as sixteen 1-byte chunks) get 200; one chunk declared at 1 MiB that never finishes gets 413 from `grow_in_buf`'s route-sized raw cap; on one keep-alive connection a 5,000-byte chunked body on an unlimited route is served and the next request's body on `/upload` still gets 413. Mutation-checked: reverting the canonical lookup, the chunked decoded check, or the raw cap each fails it.
- `test_answered.c` (`make test`, and under ASan + UBSan as `fuzz_answered` in `make fuzz` with `FUZZ_ANSWERED_ITERS`/`FUZZ_SEED`; also built against epoll in `make test_epoll`): the end-to-end "every input is answered or closed" oracle. Each input goes into a `socketpair(2)` in pieces (whole, byte by byte, every single cut, random cuts) and through the real `handle_readable`/`handle_writable`, pumped by a small level-triggered loop that follows `Connection.events_watched`. A bounded number of turns means a stuck connection fails the test. The engine's output is compared with `model_run`, a reference model that walks the whole input with the pure functions (body limit, completeness, parse, `match_route` + `dispatch` on a fake connection, `request_wire_len`, `request_wants_close`). Checked: the same statuses in order; `100 Continue` only where asked, at most once, and always for a request left waiting on its body; closed exactly when the model says, with EOF at the peer and `Connection: close` on exactly that last answer; when open, exactly the unanswered tail in `in_buf`. The model also applies the parser-independent "wait only for a short body or before any blank line" rule, so a parser bug shared by model and engine is still caught. Corpus: 32 seeds (five are body-limit bypass shapes against `/limited`), 8 pipelines, 20 pipelined requests (past `MAX_PIPELINED_PER_EVENT`) and a 414, all with exhaustive cuts, plus 3,000 random mutated inputs. Mutation-checked against 9 injected engine/parser bugs (see `improvements_progress.md`).
- `fuzz_parser.c` (`make fuzz [FUZZ_ITERS=n]`): mutation fuzzer over `request_framing` (including its `path_out`/`path_len_out` params), `request_is_complete`, `parse_http_request`, the accessors, `match_route`, `dispatch` and the response builder, compiled with ASan + UBSan and fed exact-size heap buffers (no NUL, no slack). Exit 0 means no finding (1,000,000 iterations on 2026-09-23; its "complete" count jumped sharply after the malformed-request-line fix, since malformed mutations - the bulk of what random byte-flips produce - now correctly count as complete instead of being misreported as "need more bytes"). It also compares `parse_http_request_in_place` with `parse_http_request` on every input the engine would parse (same status, same body bytes; after restoring the saved byte, a `Content-Length` request's buffer is unchanged; a failed parse writes nothing), aborting on any difference. It also asserts one behavior: for any input that frames as chunked, `chunked_body_scan_resume` run in two steps split at a random offset (state carried between them) must agree with one from-scratch `chunked_body_scan`, or it `abort()`s. It also asserts, on every input, `check_answered`'s oracle: "wait" only before any blank line (found without the parser) or while a well-framed head's body is genuinely short; a parsed head ends exactly at the first blank line, on `\r\n\r\n`; the incremental path `connection.c` takes (head re-parsed per read, `chunk_scan` carried) decides "complete" at the same prefix as a from-scratch scan; a complete prefix stays complete and gets the same answer as the whole buffer. A failure prints the oracle's line and the escaped input. `FUZZ_SEED` varies the input stream. Its first run found the short-version-token hang (`GET / X\r\n\r\n`).

There is no JSON test suite: JSON is yyjson, exercised through the cookbook and the demo handlers.

## Running
- `make test` builds and runs every suite. `make SANITIZE=1 BUILD_DIR=build-asan test` runs them all under ASan + UBSan
  (LeakSanitizer is not available on macOS). The Makefile tracks header dependencies (`-MMD`), so editing a header rebuilds every
  dependent test; before that fix, tests could silently keep an old struct layout.
- Each test binary links only the objects it needs, listed per target in the root `Makefile`. `http_parser.o` needs `arena.o` and `picohttpparser.o` too, so a new suite that parses requests must add both.
- `Connection.out_buf` built by the response layer is NUL-terminated at `out_len`, so tests may `strstr` / `strcmp` it.

## Arena in tests (parsing and responses need one)
- `parse_http_request` takes an `Arena *`, and `res_*` allocate `conn->out_buf` from `conn->arena`. Suites that call them define a global `Arena test_arena` over a `char test_arena_buf[64 * 1024]` (parse) and `arena_init(&conn.arena, buf, size)` on a zeroed fake `Connection` (responses). Reset with `arena_reset` between requests.
- `test_connection.c` goes through `connection_create`, which points `conn->arena` at `App.arena` and allocates no input buffer (`in_buf` stays NULL until bytes are left unserved); `test_response.c` builds its fake `Connection` by hand with a `malloc`'d arena buffer.

## Socket Mocking Strategy (`test_connection.c`)
- Sockets are created in pairs via `socketpair(AF_UNIX, SOCK_STREAM, 0, fds)`.
- Client simulation writes directly into `fds[1]`, and server engine reads via `handle_readable` on `fds[0]`.
- Both ends are placed into non-blocking mode with `set_nonblocking` to ensure test assertions never block on incomplete reads.

## Memory Lifecycle Rules
- Every dynamically allocated `Connection` in test fixtures must be released via `connection_close(app, conn)` or direct `free` once assertions complete (with `connection_create` the arena buffer is part of that one allocation).
- A hand-built arena buffer (`malloc` + `arena_init`) is freed by the test that created it; `arena_destroy` frees only the fallback blocks, never `buf`.
- Response and request-body bytes live in the arena; they are reclaimed by `arena_reset` / `arena_destroy`, never by `free`.
- Routes registered on an `App` are freed by `app_free_routes` (called by `app_destroy`); tests that only `free(app->connections)` leak them.
